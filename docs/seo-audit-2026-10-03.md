# SEO audit — 3 October 2026

## Scope and result

Audited 134 HTML documents: 132 canonical, indexable pages plus the deliberately
excluded search and 404 pages. Public content is static HTML, including the homepage
tool directory, so crawlers do not need JavaScript to discover the tools. No SSR
framework or build step was introduced. Existing working-tree changes were preserved.

The expanded local audit reports zero errors, duplicate titles, duplicate descriptions,
broken local links/assets, or orphan pages. Every ranking page has a self-canonical,
one H1, descriptive metadata, JSON-LD, and (apart from Home) breadcrumb UI and schema.
Search results and error/API responses retain appropriate noindex behavior.

## Changes

  22,947 → 1,764 bytes (92.3% smaller). Updated the hub generator, landing template,
  and service-worker cache. PNG app/touch icons, ICO/SVG favicons and JPEG social

  selected formats. Not every raster asset was converted.
- Corrected skipped heading levels while retaining component typography; added
  headings above category/blog collections and breadcrumbs to About, Contact,
  Privacy and Terms. Labeled existing breadcrumb navigation accessibly.
- Added visible organization attribution to 11 blog posts and six Article-marked
  photo guides, linked to the existing About page and correction contact. No personal
  qualifications, independent reviews, or professional credentials were invented.
- Added specific usage/limitations content to 12 shorter tools: word counter, age
  calculator, text to handwriting, sticker maker, upscaler, font styler, WhatsApp
  link, YouTube thumbnails, video to audio, video trim, audio cutter, and FD/RD.
  Existing contextual tool links and unique metadata were retained.
- Added explicit dimensions to static and generated preview images, including
  shared file previews. Decorative logos intentionally retain empty alt text next
  to the visible brand name; content previews have descriptive alternatives.
- Deferred independent ad-slot and analytics helpers, preserving synchronous tool
  dependencies. The mandatory asynchronous AdSense head script remains present.
- Changed self-hosted Inter to optional font display to prevent late mobile line
  wrapping. Added cache headers for modern image/font/SVG assets. Avoided rebuilding
  the homepage directory on initial load; local favorites still initialize.
- Expanded `scripts/audit-seo.mjs` to fail on heading order, missing image dimensions
  or alt attributes, missing/invalid breadcrumbs, missing article attribution,
  unexpected noindex, robots policy, redirect chains, duplicate metadata and orphans.
  Extended HTTP tests to check X-Robots-Tag on canonical pages.
- Restricted sitemap discovery to public route trees; downloaded packages, reports,
  and fixtures cannot accidentally become sitemap entries. Regenerated 132 URLs.
- Added Search Console submission CLI, mocked authentication/authorization tests,
  SEO CI, and a production-deployment/manual submission workflow. No credentials
  are embedded in static assets. Submission has not run against Google.

## Sitemap submission setup

Google retired anonymous sitemap pings. Use the supported Search Console API:
https://developers.google.com/search/blog/2023/06/sitemaps-lastmod-ping
https://developers.google.com/webmaster-tools/v1/sitemaps/submit

1. Verify `sc-domain:toolshoppy.com` in Search Console (or set `GSC_SITE_URL` to the
   exact verified URL-prefix property).
2. Enable the Search Console API in a Google Cloud project. Create a service account,
   grant it access to that Search Console property, and store its JSON key as the
   GitHub Actions secret `GSC_SERVICE_ACCOUNT_JSON`. Never commit the key.
3. Set repository variable `GSC_SITE_URL` if using a non-default property name.
4. Deploy the site and run the **Submit deployed sitemap** workflow manually once.
   Automatic runs require successful GitHub deployment-status events with the
   environment named exactly `production`. Configure the deployment integration
   to emit that event, or invoke the CLI from a post-deploy job with the same env vars.
   Do not assume Railway emits this event in the required format by default.
5. Local/CI command: `npm run sitemap:submit`. Submission is an authenticated PUT;
   success requests discovery and does not guarantee indexing or rankings.

- Configure Cloudflare to send HTTP/www/legacy route combinations directly to their
  final HTTPS apex canonical URL, preserving query strings. Exact URL mappings from
  `serve.json` plus the sitemap are safer than adding slashes to arbitrary assets.
  Recheck redirect chains after changing edge rules.
- Configure Search Console credentials and deployment events as above, then inspect
  sitemap ingestion, Page Indexing and field Core Web Vitals after deployment.
- The performance target is not fully achieved. Profile production with real ad
  fill and analytics; third-party JavaScript dominated remaining script work in
  Lighthouse. Reassess tag scheduling/ad configuration without removing required ads.
- Review time-sensitive government-photo, tax/rate and competitor claims against
  primary sources; adding attribution is not verification of every factual claim.
  Localized rate pages still need ongoing data freshness and editorial oversight.
- Add verifiable named author details only if the owner supplies them. Earn relevant
  editorial backlinks through useful original resources/outreach; these cannot be
  established by changing HTML or schema.
