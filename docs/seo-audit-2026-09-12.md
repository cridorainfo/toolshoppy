The initial production observations and remaining issues follow.

ToolShoppy is currently visible in Google. In direct, signed-out Google searches from the UAE during this audit, `toolshoppy` returned the homepage as the first web result; `pdfmerge toolshoppy` returned the PDF merge page as the first web result and as an AI Overview source. The first page for `pdf merge` did not include ToolShoppy. These are observations from one location and session, not a global rank report or a claim about the previous three months. An initial third-party search lookup returned no matches; the subsequent direct Google observations supersede that result.

At inspection, production was a static HTML/CSS/JavaScript site served by Railway's `serve` package behind Cloudflare. It contains 55 main tools, 6 category hubs, 54 location/variant pages, 11 articles plus a blog index, 5 indexable root pages, and 2 intentionally non-indexable pages (search and 404). There are 132 URLs in the sitemap. Files are generally processed in the browser; rates also depend on network data. There is no missing React SSR setup to install.

**What the public crawl establishes:** all 132 sitemap URLs returned HTTP 200. They had self-canonicals matching the sitemap, indexable robots directives, titles, descriptions, and parseable JSON-LD. No duplicate titles or descriptions were found locally. Robots.txt allows crawling and advertises the sitemap. HTTP and www requests for the merge page redirect permanently to HTTPS on the apex domain. A nonexistent page correctly returns 404. A request using a Googlebot user-agent string also received the merge page normally; this does not test requests from actual Googlebot IP addresses. These findings establish public accessibility, not that Google has indexed all 132 pages. Google's [technical requirements](https://developers.google.com/search/docs/essentials/technical) make this distinction explicit.

**Content and growth assessment:** the observed generic search is led by iLovePDF, Smallpdf, Sejda, Adobe, and other established PDF products. Competitive ranking, page usefulness, and independent recognition are reasonable areas to investigate; backlink counts and Google weighting were not measured. A public Product Hunt badge is present, so there is no basis to claim the project has zero promotion or backlinks. Prioritize a few accurate, useful workflows such as combining documents locally without upload, arranging application attachments, and preparing small final PDFs. Demonstrate those workflows on existing tool/guide pages and obtain relevant editorial mentions through real usage. Avoid generating separate near-identical pages for every spelling of “PDF merge.” Google's [helpful-content guidance](https://developers.google.com/search/docs/fundamentals/creating-helpful-content) and [spam policies](https://developers.google.com/search/docs/essentials/spam-policies) support usefulness over generating pages primarily for search terms. No manual action or spam classification was confirmed.

**Other review items:** `_headers` contains hosting rules that Railway `serve` does not read; `serve.json` is the active configuration. This is a configuration-maintenance trap, not an observed noindex problem. Financial/application pages should identify their sources and review dates; this audit did not validate every tax bracket or government photo requirement. The PDF guide and FAQ should distinguish reordering whole files from editing individual pages. These are editorial/functional follow-ups, not reasons to change a working canonical URL.

**Measurement limits:** DNS contains a Google site-verification TXT record. The commented-out HTML verification placeholder therefore does not establish that Search Console is unverified. Authenticated Search Console reports, actual Googlebot logs, historical positions, manual actions/security reports, backlink counts, and field Core Web Vitals were unavailable. The anonymous PageSpeed API returned HTTP 429 (quota exceeded), so no Lighthouse score or Core Web Vitals pass is claimed. The local mobile homepage was visually checked at a 375px viewport with no horizontal overflow; this is not a substitute for performance measurements. Individual processing flows for all 55 tools were not exhaustively tested.
